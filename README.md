# TikTok Lead Hunter

> **Новый отдельный API:** исследование, FastAPI + PostgreSQL + Celery/Redis,
> OAuth, Docker и проверяемая очередь комментариев описаны в [README_API.md](README_API.md).
> Локальный запуск нового сервиса: `start-api.bat`, порт **8001**.
> Приложение ниже — существующая браузерная версия на порту 8000.

Локальная панель для поиска роликов TikTok, отбора лидов и отправки комментариев.
Python + FastAPI + SQLite + Playwright. Интерфейс на обычных HTML, CSS и JavaScript,
без сборки и внешних CDN. Иконки Tabler поставляются локально с MIT-лицензией.

## Запуск

Нужен Python 3.11+. Запустите `start.bat`: при первом запуске установятся зависимости
и Chromium. Панель откроется по адресу http://127.0.0.1:8000.

Вручную:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m playwright install chromium
.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Используйте один процесс сервера, без нескольких workers. Документация API: `/docs`.

## Подключение аккаунта

1. Откройте **Аккаунты → Добавить аккаунт**.
2. Укажите **обязательный прокси**, его протокол и браузер.
3. Нажмите **Продолжить**. В разделе **Подключение TikTok** откроется инструкция:
   войдите в TikTok в обычном Chrome, нажмите `F12`, откройте
   **Application → Storage → Cookies → https://www.tiktok.com**.
4. В фильтре найдите точное имя **sessionid**. Скопируйте только значение из колонки
   **Value**, вставьте его в поле панели и нажмите **Подключить аккаунт**.
5. Панель проверит прокси и sessionid в отдельном фоновом браузере. Только после
   подтверждения фактического аккаунта сервером TikTok он появится в списке.

В разделе **Другой способ входа** можно открыть отдельное окно TikTok через тот же
прокси и войти по почте или телефону (до пяти минут). Вход через Google в управляемом
браузере может быть недоступен.

Подходят `host:port`, `host:port:login:password`, `login:password@host:port`
и полные HTTP/HTTPS/SOCKS5 URL. SOCKS5 с паролем Chromium не поддерживает.
Если Google Chrome не установлен, выберите встроенный Chromium.

Для HTTP/HTTPS-прокси с паролем используется временный локальный посредник на
`127.0.0.1`: он передаёт авторизацию провайдеру прокси, чтобы обработка авторизации
в Playwright не прерывала загрузку ресурсов TikTok. HTTPS-трафик не расшифровывается.
Посредник закрывается вместе с браузером; прямого подключения в обход прокси нет.

У каждого аккаунта собственные прокси и файл входа `data/session/accounts/{id}.json`.
Браузерные данные задач сохраняются также в отдельном постоянном профиле
`data/session/browsers/{id}/`. Повторное подключение или смена прокси создают
новый профиль. Существующий профиль не перезаписывается старым файлом cookies
при каждом запуске. Для этого требуется Playwright 1.59 или новее.
Перед публикацией приложение ждёт успешной загрузки комментариев. Капча,
появившаяся после открытия поля ввода, также приостанавливает отправку до ручной
проверки. Если комментарии не загрузились, клик отправки не выполняется.
Поиск и автоотправка используют выбранный аккаунт, его прокси и его cookies.
Пароли прокси не выдаются в API аккаунтов или задач и не показываются в списке.
Значение sessionid не попадает в параметры задач, ответы API и журнал. До проверки
оно хранится в отдельном временном файле, который удаляется при ошибке или отмене.
Незавершённые подключения хранятся отдельно от аккаунтов и удаляются после завершения,
отмены, ошибки либо восстановления после перезапуска. Прямого подключения при отказе
прокси нет.

Старые записи и история сохраняются. Аккаунты без подтверждённого подключения находятся
в свёрнутом разделе **Требуют подключения**. Для их использования войдите заново через
новый мастер. Добавление по нику и импорт общей сессии отключены; импорт sessionid
выполняется для конкретного подключения с его прокси.

## Рабочий процесс

- **Обзор** показывает сводку и предлагает следующий шаг.
- **Поиск** принимает до 20 запросов, каждый с новой строки, и до 200 роликов на запрос.
  Выберите аккаунт. Шаблон позволяет сразу подготовить ответы для всех новых роликов.
- **Ролики** позволяют искать по автору или тексту, фильтровать по запросу и статусу,
  отмечать подходящие ролики и создавать черновики. Поддерживается массовый выбор.
- **Шаблоны** поддерживают `{Привет|Здравствуйте}`, `[author]` и `[query]`,
  редактирование и предварительный просмотр вариантов.
- **Очередь** содержит список ответов и редактор выбранного черновика.
  Кнопка **Отправить** публикует один комментарий. **Автоотправка** в заголовке
  запускает пакет с количеством и паузой (по умолчанию 5 ответов и 60 секунд).
- **Вручную** открывает действия копирования и учёта публикаций. Клавиши:
  `O` открыть и скопировать, `Enter` отметить отправленным и перейти дальше,
  `S` пропустить, `E` редактировать, `Ctrl+Enter` отметить из редактора, `Esc` выйти.
  Выбранный аккаунт запоминается. Обычная вкладка TikTok в ручном режиме использует
  сеть и аккаунт вашего обычного браузера; прокси панели действует на автоматические операции.
- **Журнал** содержит события и ошибки. В **Настройках** можно выбрать светлую,
  тёмную или системную тему.

## Подтверждение и остановка отправки

Автоотправка реализована через Playwright. Библиотека davidteather/TikTok-Api
не подключена: у неё нет методов публикации комментариев.

Перед публикацией проверяются фактический аккаунт TikTok, статус аккаунта и дневной лимит.
Лимит учитывает отправленные сегодня, зарезервированные черновики и неопределённые
публикации. Занятые черновики защищены от редактирования и удаления.

Статус **Отправлен** выставляется только при успешном ответе TikTok с ID комментария,
правильными текстом, автором и роликом. Это подтверждение приёма, дальнейшая видимость
может зависеть от модерации TikTok. При ошибке задача останавливается без автоматического повтора.

Кнопка **Остановить** прерывает подготовку до нажатия кнопки публикации. Уже начатая
публикация ожидает подтверждения без повторной отправки. В панели виден текущий этап:
загрузка ролика, открытие комментариев, проверка аккаунта и подтверждение TikTok.
Если TikTok отключил комментарии к ролику, отправка завершается с объяснением причины.
Баннер дополнительных cookies отклоняется автоматически, затем открывается вкладка
комментариев, включая значок справа от ролика. Скрытые вкладки уведомлений не
используются. Капча проходится вручную в видимом окне (до трёх минут).

Пустой HTTP 200 от TikTok не считается успешной публикацией: комментарий получает
статус **Нужна проверка** без автоматического повтора. В `data/diagnostics/`
сохраняются снимок страницы и сведения о запросе/ответе без значений cookies,
паролей, токенов и полного адреса запроса.

При неизвестном результате или перезапуске во время публикации ответ получает статус
**Нужна проверка**. В фильтре **Проверить публикацию** откройте ролик и выберите
**Комментарий опубликован** или **Комментария нет**. Только после проверки возможен повтор.

## Экспорт

**Ролики → Экспорт** выгружает лиды с текущими фильтрами.
**Очередь → Отчёт** выгружает отправленные ответы за выбранный период.
CSV: UTF-8 с BOM, разделитель `;`, совместим с Excel и Google Sheets.

## Данные и обновление

Данные находятся в `data/` (путь переопределяется через `TTLH_DATA_DIR`).
Обновление старой базы добавляет новые поля без удаления записей.
Перед переработкой сохранены `data/backups/before-account-proxies.db`
и `data/backups/before-redesign.zip`.

## Проверки

```powershell
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python -m unittest discover -s tests -v
```

Тесты используют временную БД и подменяют сеть TikTok. Реальная авторизация
и публикация комментариев в тестах не выполняются.

Основные API: `/api/accounts/connect`, `/api/accounts/connection/latest`,
`/api/accounts/{id}/select`, `/api/accounts/{id}/check`, `/api/tasks/search`,
`/api/tasks/auto-comment`, `/api/tasks/{id}/stop`, `/api/drafts/{id}/resolve`.
